# Support

For help with the iPhone app, an account, or private details, use the public [Pushman support page](https://app.pushman.whitekiwi.link/support/). It provides an email contact and does not require a GitHub account.

For a reproducible product bug or feature proposal that contains no private data, search the [Pushman issue tracker](https://github.com/pushmanhq/pushman/issues) before opening a new issue.

For CLI-specific build, packaging, or command behavior, use the [`pushman-cli` issue tracker](https://github.com/pushmanhq/pushman-cli/issues). Run `pushman doctor` first when the problem concerns authorization, credentials, connectivity, or delivery.

Include the app or CLI version, operating system, visible error code, expected result, and redacted output. Never post notification content, complete URLs, tokens, OAuth data, pairing codes, account identifiers, local paths, or private logs.

For Windows CLI reports, add the Windows build, x64/ARM64 architecture, shell/version, installation method, and exit code. Describe executable path characteristics such as spaces or non-ASCII characters without sharing the actual private path. Credential access may differ between an interactive desktop, another user/elevation, SSH, CI, and Task Scheduler sessions.

Suspected vulnerabilities belong in private vulnerability reporting, not a public issue. Follow [SECURITY.md](SECURITY.md).
